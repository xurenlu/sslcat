# SSLcat - SSL Прокси Сервер

## ⏱️ Быстрый Старт с SSLcat за 1 Минуту

```bash
# 1) Быстрый тест на macOS локально (или скачать darwin пакет вручную)
curl -fsSL https://sslcat.com/xurenlu/sslcat/releases/download/v1.3.3/sslcat_v1.3.3_darwin-arm64.tar.gz -o sslcat.tgz
tar -xzf sslcat.tgz && sudo install -m 0755 sslcat /usr/local/bin/sslcat
sslcat --config sslcat.conf --port 8080
# Доступ через браузер: http://localhost:8080/sslcat-panel/
# Первый вход: admin / admin*9527
# ⚠️ Первый вход принудит: 1) Смена пароля 2) Пользовательский путь панели
# Пожалуйста, запомните новый путь панели управления!

# 2) Опционально: Запуск одним кликом через Docker Compose
docker compose up -d
```

SSLcat — это мощный SSL прокси-сервер, который поддерживает автоматическое управление сертификатами, перенаправление доменов, защиту безопасности и веб-панель управления, с поддержкой протоколов HTTP/3 (QUIC) и HTTP/2 (автоматическое согласование, обратная совместимость).

## 🚀 Установка и Развертывание

### Ручная Установка

1. **Установить Зависимости**
```bash
# Ubuntu/Debian
sudo apt-get update
sudo apt-get install -y curl wget git build-essential ca-certificates certbot

# CentOS/RHEL
sudo yum update -y
sudo yum install -y curl wget git gcc gcc-c++ make ca-certificates certbot
```

2. **Установить Go**
```bash
# Скачать и установить Go 1.21
wget https://go.dev/dl/go1.21.5.linux-amd64.tar.gz
sudo tar -C /usr/local -xzf go1.21.5.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
source ~/.bashrc
```

3. **Скомпилировать SSLcat**
```bash
git clone https://github.com/xurenlu/sslcat.git
cd sslcat
go mod download
go build -o sslcat main.go
```

4. **Создать Пользователя и Директории**
```bash
sudo useradd -r -s /bin/false sslcat
sudo mkdir -p /etc/sslcat /var/lib/sslcat/{certs,keys,logs}
sudo chown -R sslcat:sslcat /var/lib/sslcat
```

5. **Настроить и Запустить**
```bash
sudo cp sslcat /opt/sslcat/
sudo cp sslcat.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable sslcat
sudo systemctl start sslcat
```

## Конфигурация

### Расположение Файла Конфигурации
- Основной файл конфигурации: `/etc/sslcat/sslcat.conf`
- Директория сертификатов: `/var/lib/sslcat/certs`
- Директория ключей: `/var/lib/sslcat/keys`
- Директория логов: `/var/lib/sslcat/logs`

### Базовая Конфигурация

```json
{
  "server": {
    "host": "0.0.0.0",
    "port": 443,
    "debug": false
  },
  "ssl": {
    "email": "your-email@example.com",
    "staging": false,
    "auto_renew": true
  },
  "admin": {
    "username": "admin",
    "password_file": "./data/admin.pass",
    "first_run": true
  },
  "proxy": {
    "rules": [
      {
        "domain": "example.com",
        "target": "127.0.0.1",
        "port": 8080,
        "enabled": true,
        "ssl_only": true
      }
    ]
  },
  "security": {
    "max_attempts": 3,
    "block_duration": "1m",
    "max_attempts_5min": 10
  },
  "admin_prefix": "/sslcat-panel"
}
```

### Восстановление Пароля (Экстренное Восстановление)

SSLcat использует стратегию безопасности "файл-маркер + принудительная смена пароля при первом использовании":

- Файл-маркер: `admin.password_file` (по умолчанию `./data/admin.pass`). Файл сохраняет текущий пароль администратора с правами 0600.
- Первый вход: Если файл-маркер не существует, или содержимое файла по-прежнему является паролем по умолчанию `admin*9527`, администратор будет принудительно перенаправлен на страницу "смена пароля" после успешного входа для установки нового пароля и записи в файл-маркер.

Шаги восстановления пароля:

1. Остановить сервис (или оставить работающим, рекомендуется остановить).
2. Удалить файл-маркер (если путь изменился, удалить согласно реальному пути конфигурации):
   ```bash
   rm -f ./data/admin.pass
   ```
3. Перезапустить сервис, войти с учетной записью по умолчанию (admin / admin*9527).
4. Система принудительно перейдет на страницу "смена пароля", установить новый пароль для восстановления нормальной работы.

Примечание: По соображениям безопасности, `sslcat.conf` больше не сохраняет `admin.password` в открытом виде при сохранении; во время выполнения фактический пароль использует `admin.password_file` как стандарт.

## Веб-Панель Управления

### Доступ к Панели Управления

**⚠️ Важно: Метод Первоначального Доступа**

Поскольку система не имеет SSL сертификатов при первой установке, пожалуйста, используйте следующий метод для первоначального доступа:

1. **Первый Доступ** (используя IP адрес сервера):
   ```
   http://YOUR_SERVER_IP/sslcat-panel
   ```
   Примечание: Используйте `http://` (не https), поскольку SSL сертификатов еще нет

2. **После настройки домена и получения сертификатов**:
   ```
   https://your-domain/your-custom-panel-path
   ```

**Процесс Входа:**
1. Войти с учетными данными по умолчанию:
   - Имя пользователя: `admin`
   - Пароль: `admin*9527`
2. Первый вход принудит:
   - Изменить пароль администратора
   - Персонализировать путь доступа к панели (для безопасности)
3. **Пожалуйста, запомните новый путь панели!** Система автоматически перенаправит на новый путь

### Функции Панели Управления
- **Панель Мониторинга**: Просмотр состояния системы и статистики
- **Конфигурация Прокси**: Управление правилами перенаправления доменов
- **SSL Сертификаты**: Просмотр и управление SSL сертификатами
- **Настройки Безопасности**: Настройка политик безопасности и просмотр заблокированных IP
- **Системные Настройки**: Изменение конфигурации системы

## Конфигурация Прокси

### Добавление Правила Прокси
1. Войти в панель управления
2. Перейти на страницу "Конфигурация Прокси"
3. Нажать "Новое Правило Прокси"
4. Заполнить конфигурацию:
   - Домен: Домен для проксирования
   - Цель: IP или домен backend сервера
   - Порт: Порт backend сервиса
   - Включено: Включить ли это правило
   - Только SSL: Разрешить ли только HTTPS доступ

### Пример Правила Прокси
```json

  "proxy": {
    "rules": [
      {
        "domain": "api.example.com",
        "target": "127.0.0.1",
        "port": 3000,

        "ssl_only": true
      },
      {
        "domain": "app.example.com",
```

## Управление SSL Сертификатами

### Автоматическое Получение Сертификатов
SSLcat автоматически получает SSL сертификаты для настроенных доменов без ручного вмешательства.

### Обновление Сертификатов
Сертификаты автоматически обновляются за 30 дней до истечения срока, или могут быть запущены вручную.

### Хранение Сертификатов
- Файл сертификата: `/var/lib/sslcat/certs/domain.crt`
- Файл приватного ключа: `/var/lib/sslcat/keys/domain.key`

## Функции Безопасности

### Механизм Блокировки IP
- Автоматическая блокировка после 3 неудачных попыток за 1 минуту
- Автоматическая блокировка после 10 неудачных попыток за 5 минут
- Настраиваемая длительность блокировки
- Поддержка ручной разблокировки

### Контроль Доступа
- Валидация User-Agent
- Отклонение доступа с пустым User-Agent
- Отклонение доступа с необычным User-Agent браузера

### Разблокировка IP
```bash
# Удалить файл блокировки и перезапустить сервис
sudo rm /var/lib/sslcat/sslcat.block
sudo systemctl restart sslcat
```

## Аргументы Командной Строки

```bash
sslcat [опции]

Опции:
  --config string        Путь к файлу конфигурации (по умолчанию: "/etc/sslcat/sslcat.conf")
  --admin-prefix string  Префикс пути панели управления (по умолчанию: "/sslcat-panel")

  --staging             Использовать staging окружение Let's Encrypt
  --port int            Порт прослушивания (по умолчанию: 443)
  --host string         Адрес прослушивания (по умолчанию: "0.0.0.0")
  --log-level string    Уровень логирования (по умолчанию: "info")
  --version             Показать информацию о версии
```

## Устранение Неполадок

### Распространенные Проблемы

1. **Сбой запуска сервиса**
   ```bash
   # Проверить синтаксис файла конфигурации
   sudo withssl --config /etc/sslcat/sslcat.conf --log-level debug
   
   # Проверить использование порта
   sudo netstat -tlnp | grep :443
   ```

2. **Сбой получения SSL сертификата**
   - Убедиться, что разрешение домена корректно
   - Убедиться, что порт 80 доступен
   - Проверить настройки брандмауэра
   - Использовать staging окружение для тестирования

3. **Сбой перенаправления прокси**
   - Проверить, доступен ли целевой сервер
   - Проверить правильность порта
   - Проверить логи доступа

4. **Недоступна панель управления**
   - Проверить настройки брандмауэра
   - Проверить валидность SSL сертификата
   - Проверить логи сервиса

## Оптимизация Сети

### Оптимизация для Пользователей Континентального Китая

Проект SSLcat был оптимизирован для сетевой среды континентального Китая, используя прокси-сервис [CDNProxy](https://cdnproxy.shifen.de/docs) для решения проблем доступа к jsdelivr CDN.

#### Использование CDN Прокси
- **Оригинальный адрес**: `https://cdn.jsdelivr.net/npm/bootstrap@5.1.3/dist/css/bootstrap.min.css`
- **Прокси адрес**: `https://cdnproxy.shifen.de/cdn.jsdelivr.net/npm/bootstrap@5.1.3/dist/css/bootstrap.min.css`

#### Задействованные Файлы Ресурсов
- Bootstrap 5.1.3 CSS
- Bootstrap Icons 1.7.2
- Bootstrap 5.1.3 JavaScript
- Библиотека Axios JavaScript

#### Контроль Доступа
Согласно документации CDNProxy, сервис реализует политики контроля доступа. Если доступ заблокирован, обычно это происходит потому, что домен Referer запроса не находится в белом списке. Свяжитесь с администратором сервиса для добавления вашего домена в белый список при необходимости.
