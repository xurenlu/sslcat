## 🎯 核心特性

### 1. 智能提示词设计

**系统提示词特点：**
- 角色定位：专业网络安全分析专家
- 任务明确：威胁识别、等级评估、建议生成
- 分析重点：DDoS、扫描、异常UA、地理位置、时间模式
- 输出规范：标准 JSON 格式，包含置信度

**用户提示词特点：**
- 动态生成：基于实时数据
- 结构化：基础统计 + 攻击事件 + Top攻击者 + 异常UA
- 精简：只包含关键信息，控制 token 消耗

### 2. 数据收集与聚合

**DDoS 数据：**
- 总请求数、被封禁 IP 数、可疑 IP 数
- 攻击事件分类统计（类型、数量、严重程度）
- Top 攻击者（IP、请求数、封禁次数、请求速率）

**安全日志数据：**
- 异常 User-Agent 统计
- 唯一 IP 数量
- 可疑原因标注

**数据去重：**
- 基于数据摘要 hash 缓存结果
- 避免重复分析相同数据
- 降低 API 调用成本

### 3. 威胁分级与通知

**威胁等级：**
- `low` - 低威胁，仅记录
- `medium` - 中等威胁，发送通知
- `high` - 高威胁，发送通知
- `critical` - 严重威胁，发送通知

**通知策略：**
- 可配置最低通知等级
- 邮件包含完整分析报告
- 置信度标注
- 可操作的安全建议

### 4. 成本优化

**策略：**
- 使用 GPT-4 mini（最便宜的模型）
- 检查间隔默认 1 小时
- 设置最少事件数阈值（默认 10）
- 结果缓存，避免重复分析

**实际成本：**
- 单次分析：$0.001-0.003
- 每天（24次）：$0.024-0.072
- 每月：$0.72-2.16
- **年度成本约 $10-25**

## 🚀 使用流程

### 1. 配置

```bash
# 1. 获取 OpenAI API Key
# 访问 https://platform.openai.com/api-keys

# 2. 编辑配置文件
vim sslcat.conf

# 3. 添加 ai_security 和 notification 配置

# 4. 保护 API Key 安全
chmod 600 sslcat.conf
```

### 2. 启动

```bash
# 编译
go build -o sslcat main.go

# 启动
./sslcat

# 查看日志
tail -f logs/sslcat.log | grep "ai_security"
```

### 3. 验证

检查日志中是否有：

```
[INFO] ai_security: AI 安全分析器已启动，检查间隔: 1h
[INFO] ai_security: 开始执行 AI 安全分析...
[INFO] ai_security: GPT API 调用成功，使用 tokens: 1245
[INFO] ai_security: AI 分析完成，威胁等级: medium，置信度: 0.85
```

### 4. 接收通知

当检测到威胁时，你会收到邮件：

```

置信度: 90%

1. 将该 IP 加入黑名单
2. 检查攻击目标
```

## 🔐 安全注意事项

### API Key 保护

- ❌ 不要将 API Key 提交到 Git
- ✅ 使用环境变量
- ✅ 配置文件权限 600
- ✅ 定期轮换

### 数据隐私

- 发送给 GPT 的数据已脱敏（IP、UA 等）
- 不包含请求详细内容
- 只包含统计摘要

### 速率限制

- OpenAI 有速率限制
- 检查间隔不要小于 30 分钟
- 监控 API 使用量

## 🐛 常见问题

### Q1: 为什么没有启动？

A: 检查：
- `ai_security.enabled` 是否为 `true`
- `api_key` 是否正确
- 查看日志错误信息

### Q2: 为什么没收到邮件？

A: 检查：
- 通知配置是否正确
- 威胁等级是否低于 `min_threat_level`
- 查看日志中的通知发送记录

### Q3: API 调用失败？

A: 可能原因：
- API Key 无效
- 网络无法访问 OpenAI
- 速率限制
- 账户余额不足

### Q4: 成本过高？

A: 优化方法：
- 增加 `check_interval`（如 2h、4h）
- 提高 `min_events` 阈值
- 减少 `max_tokens`
