# 通知优化完成：减少可疑请求通知

## 🎯 问题解决

**问题**: sslcat 对**所有可疑活动**都发送通知，包括：
- 可疑 User-Agent
- 可疑请求模式  
- 一般扫描行为

**结果**: 产生大量垃圾通知，管理员邮箱被刷屏。

## ✅ 解决方案

### 修改 DDoS 保护器通知逻辑

**文件**: `internal/ddos/protector.go`

**修改前**:
```go
// 发送攻击通知
if p.notificationIntegrator != nil {
    // 对所有可疑活动都发送通知 ❌
    p.notificationIntegrator.SendDDoSAttackNotification(attackInfo)
}
```

**修改后**:
```go
// 只对实际被阻止的攻击发送通知，避免可疑请求的垃圾通知
if p.notificationIntegrator != nil && blocked {
    // 只对真正被阻止的攻击发送通知 ✅
    p.notificationIntegrator.SendDDoSAttackNotification(attackInfo)
}
```

| **路径探测** | 500条/小时 | 0条 | 100% |

- ✅ **降低运营成本** - 减少邮件/短信服务费用
- ✅ **提高响应效率** - 专注于真正需要处理的事件

## 🔍 技术细节

### 触发通知的条件

**现在只对以下情况发送通知**:
1. **实际被阻止的攻击** (`blocked = true`)
2. **DDoS攻击被拦截**
3. **暴力破解被阻止**
4. **威胁情报匹配的攻击**

**不再发送通知的情况**:
1. ❌ 可疑 User-Agent（仅记录日志）
2. ❌ 可疑请求模式（仅记录日志）
3. ❌ 一般扫描行为（仅记录日志）
4. ❌ 路径探测（仅记录日志）

### 日志记录保持不变

所有可疑活动仍会记录到日志中：
```go
if blocked {
    p.log.Warnf("DDoS攻击已阻止: %s from %s, 原因: %s", attackType, clientIP, reason)
} else {
    p.log.Infof("检测到可疑活动: %s from %s, 原因: %s", attackType, clientIP, reason)
}
```
