# GOGC 参数详解

## 什么是 GOGC？

`GOGC` 是 Go 语言垃圾回收器（Garbage Collector）的触发阈值参数。它控制何时触发垃圾回收。

## 工作原理

### 基本公式

```
触发 GC 的时机 = 上次 GC 后的内存使用量 × (1 + GOGC/100)
```

### 具体示例

#### GOGC=100（默认值，平衡模式）

假设上次 GC 后内存使用量为 100MB：

```
触发 GC 的时机 = 100MB × (1 + 100/100) = 100MB × 2 = 200MB
```

**含义**：
- 当内存使用量增长到 **200MB** 时触发 GC
- 即内存增长 **100%**（翻倍）时触发
- 这是 Go 的默认值，在内存占用和 GC 频率之间取得平衡

#### GOGC=300（低流量优化模式）

假设上次 GC 后内存使用量为 100MB：

```
触发 GC 的时机 = 100MB × (1 + 300/100) = 100MB × 4 = 400MB
```

**含义**：
- 当内存使用量增长到 **400MB** 时触发 GC
- 即内存增长 **300%**（4倍）时触发
- GC 频率更低，CPU 占用更少，但内存占用会略高

## 不同 GOGC 值的对比

| GOGC 值 | 内存增长倍数 | 触发时机（从100MB） | GC 频率 | CPU 占用 | 内存占用 | 适用场景 |
|---------|------------|-------------------|---------|---------|---------|---------|
| 50      | 1.5倍      | 150MB            | 很高    | 高      | 低      | 内存受限环境 |
| 100     | 2倍        | 200MB            | 中等    | 中等    | 中等    | 默认，平衡模式 |
| 200     | 3倍        | 300MB            | 较低    | 较低    | 较高    | 高流量场景 |
| 300     | 4倍        | 400MB            | 低      | 低      | 高      | 低流量场景（推荐） |

## 实际影响

### GOGC=100 的问题

**场景**：低流量 web server，每秒分配 3.39MB 内存

```
内存分配速率：3.39MB/秒
上次 GC 后内存：100MB
触发 GC 时机：200MB（增长 100MB）

触发时间：100MB ÷ 3.39MB/秒 ≈ 29.5 秒
```

**结果**：
- 每 30 秒触发一次 GC
- GC 占用大量 CPU（41.81%）
- CPU 使用率：193.3%

### GOGC=300 的改善

**场景**：同样的低流量 web server

```
内存分配速率：3.39MB/秒
上次 GC 后内存：100MB
触发 GC 时机：400MB（增长 300MB）

触发时间：300MB ÷ 3.39MB/秒 ≈ 88.5 秒
```

**结果**：
- 每 90 秒触发一次 GC（频率降低 3 倍）
- GC 占用 CPU 大幅减少
- CPU 使用率：0.2%

## 权衡

### GOGC 值越高

**优点**：
- ✅ GC 频率更低
- ✅ CPU 占用更少
- ✅ 适合低流量场景

**缺点**：
- ❌ 内存占用更高
- ❌ 单次 GC 时间可能更长
- ❌ 不适合内存受限环境

### GOGC 值越低

**优点**：
- ✅ 内存占用更低
- ✅ 单次 GC 时间更短
- ✅ 适合内存受限环境

**缺点**：
- ❌ GC 频率更高
- ❌ CPU 占用更高
- ❌ 不适合高流量场景

## 推荐配置

### 低流量场景（推荐）

```bash
GOGC=300
GOMEMLIMIT=512MiB
```

**理由**：
- 流量低，内存分配慢
- 高 GOGC 值减少 GC 频率
- 内存占用略高但可接受

### 中等流量场景

```bash
GOGC=200
GOMEMLIMIT=1GiB
```

**理由**：
- 平衡 GC 频率和内存占用
- 适合大多数场景

### 高流量场景

```bash
GOGC=100
GOMEMLIMIT=2GiB
```

**理由**：
- 流量高，内存分配快
- 需要更频繁的 GC 控制内存
- Go 默认值，经过优化

### 内存受限环境

```bash
GOGC=50
GOMEMLIMIT=256MiB
```

**理由**：
- 内存非常有限
- 需要更频繁的 GC 释放内存
- CPU 占用会较高

## 如何设置

### 方式 1: 环境变量（推荐）

```bash
# systemd service
Environment="GOGC=300"

# 命令行
export GOGC=300
./sslcat
```

### 方式 2: 代码中设置

```go
import "runtime/debug"

debug.SetGCPercent(300)
```

### 方式 3: 配置文件

在 `sslcat.conf` 中设置（如果支持）

## 监控和调优

### 查看 GC 统计

```bash
# 启用 GC 跟踪
export GODEBUG=gctrace=1

# 查看输出
# gc 1 @0.001s 2%: 0.010+0.20+0.002 ms clock, 0.040+0.10/0.15/0.05+0.010 ms cpu, 4->4->0 MB, 5 MB goal, 4 P
```

**字段说明**：
- `@0.001s`: GC 开始时间
- `2%`: GC 占用 CPU 百分比
- `4->4->0 MB`: GC 前内存 -> GC 后内存 -> 释放内存
- `5 MB goal`: GC 目标内存

### 调优建议

1. **观察 GC 频率**
   - 如果 GC 太频繁（< 1 分钟），提高 GOGC
   - 如果 GC 太少（> 5 分钟），降低 GOGC

2. **观察 CPU 占用**
   - 如果 GC 占用 CPU > 10%，提高 GOGC
   - 如果内存占用过高，降低 GOGC

3. **观察内存占用**
   - 如果内存占用过高，降低 GOGC
   - 如果内存占用正常，可以提高 GOGC 减少 CPU

## 总结

- **GOGC=100**: 内存增长 2 倍时触发 GC（默认，平衡模式）
- **GOGC=300**: 内存增长 4 倍时触发 GC（低流量优化，减少 GC 频率）

对于低流量的 web server，**GOGC=300** 可以显著减少 GC 频率和 CPU 占用，是更好的选择。
