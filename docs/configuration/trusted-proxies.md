# Web 客户端 IP 与可信代理

本轮修改使 `internal/web` 的 `getClientIP` 默认忽略转发头，仅返回直接连接的对端 IP。私网和回环地址也需要显式授权。IPv4、IPv6 和带端口地址通过 IP/主机端口解析处理。

## 配置

在 JSON 配置的 `server` 中列出实际代理地址，例如只有 `192.0.2.10` 这一台前置代理：

```json
{
  "server": {
    "trusted_proxies": ["192.0.2.10"],
    "trusted_proxy_header": "X-Forwarded-For"
  }
}
```

示例地址需替换为部署中的代理 IP。`trusted_proxies` 接受 IPv4/IPv6 地址或 CIDR；应尽量使用单个代理地址或专用小网段，避免信任整个私网。空列表不信任任何来源，无效条目不会授予信任。

`trusted_proxy_header` 省略时使用 `X-Forwarded-For`。也可明确选择 `X-Real-IP` 或 `CF-Connecting-IP`，只读取所选头；未知值回退为对端 IP。使用单地址头时只接受一个有效值。前置代理必须覆盖客户端传入的同名头；仅配置代理 IP 并不能证明头中的地址真实。

## 代理链

只有直接对端命中信任列表，才读取所选转发头。`X-Forwarded-For` 合并同名头后从右向左扫描，跳过可信代理，在第一个不可信地址处停止；到达无效地址时终止解析并回退为直接对端，避免跨越无效的信任边界。不能确定客户端地址时同样回退为对端。

例如直接对端是可信的 `192.0.2.10`，头为 `203.0.113.99, 198.51.100.20`，且 `198.51.100.20` 不可信，则返回后者，不接受最左边可能由客户端伪造的地址。

## 范围与迁移

此配置约束 Web 层 `getClientIP` 的调用者。项目中 WAF、代理及其他安全组件还有独立 IP 提取函数，本轮不代表它们已统一使用这一策略，详见 [设计审查](../design-review.md)。

部署在前置代理后的用户需要显式配置可信代理，否则这些 Web 调用者看到的是代理 IP；升级前应核对登录、审计和管理限流的实际来源地址。
